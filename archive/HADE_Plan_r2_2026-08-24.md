## §1 上一轮留下的三笔账

### 账 1 · 本体与副本的同步无机制（**这轮引入的**，优先级最高）

`~/.claude/CLAUDE.md`（生效的本体）与
`plugins/hade-core/install/CLAUDE.md`（仓库副本、版本化的那份）
靠手动同步维持。当前 hash 一致，但**没有任何机制阻止它们漂移**。

重构前只有一份本体，不存在这个问题 —— 这是三层结构的代价，必须还。

**候选解（按优先级）：**

| 方案 | 做法 | 风险 |
|---|---|---|
| A 硬链接 | `mklink /H` 让两个路径指向同一份数据 | ⚠ **必须先实测**：很多编辑器保存是「写临时文件 + 改名替换」，这会**断链**且断得无声无息 |
| B hash 探针 | SessionStart hook 里比对两份 hash，不一致就把警告吐进上下文 | 只报警不修复；但**无声漂移变成有声** |
| C 单向同步脚本 | `sync_global.py`，并挂进 §七 备份动作 | 靠记得跑；本轮全程证明"靠记得"不可靠 |

**建议：A 做实测，成则 A + B 双保险；A 不成则 B + C。**
B 无论如何都要做 —— 它是唯一能把"无声漂移"变成"有声"的一层。

**A 的实测方法（不许跳过）：**
建链 → 用你实际编辑 Global 的方式改一个字（Edit 工具、记事本、VS Code 各试一次）
→ 每次改完检查两个路径的 inode / 文件 ID 是否仍相同。**任一编辑器断链，A 即否决。**

### 账 2 · 验收数字陈旧

`PLAN-AND-EXECUTION-LOG.md` 的汇总表写「−197 行 / −18.1% / 892 行 / 72167 字节」，
实测是「−198 / −18.2% / 891 行 / 72327 字节（CRLF）」。
最后两次提交后汇总表没回头更新。**顺手改，并在表旁注明字节口径是 CRLF。**

### 账 3 · 记账口径缺一格

「规则措辞删除或改写 0 处」这句话，把 §七 完整性自检那处**加例外条款**归到了"新增/调整"。
但给一条安全闸门开口子，风险级别高于加一条新规则，该单独记。

**动作**：在执行日志的记账口径里补第三格 ——
`规则性新增/调整` · `范围声明扩容` · **`安全条款例外化`**。
上一轮那处归入第三格并补一句"为什么这个例外不会被滥用"。

## §3 新机会：hook 是被低估的一层（**本轮最大赌注**）

### 问题重述

R1（触发欠敏）在上一轮**没有被解决**，只是被"工具容器"绕开了：
规则留本体保证不丢，但 `local-storage-safety` 的触发率仍是 **0/9，两种形态都是**。
它现在是一个不会自己醒来的工具 —— 只有手动 `/skill` 才用得上。

而已经验证过的事实是：**SessionStart hook 100% 触发，description 匹配 0%。**
差别不在内容写得好不好，在**触发权归谁**。

### 赌注：第四种形态 —— hook 容器

```
知识容器   正文进 skill，Global 删除      触发靠 description   有下行风险
工具容器   规则留 Global，skill 装脚本     触发靠 description   无下行风险，但仍是 0%
纯档案     内容进 archive，Global 留指针   靠 Global 指针       可达
hook 容器  规则留 Global，脚本挂 hook      触发靠工具调用事件    ← 本轮要验的
```

**具体设想**：`PreToolUse` / `PostToolUse` hook 匹配对 `package.json` /
`electron/main.js` 的写入 → 自动跑 `check_electron_safety.py` → 结果进上下文。

这样 §九.I 的确定性检查**不再依赖模型想不想调工具**，而是依赖"文件被改了"这个客观事件。

### 必须先核验的三件事（**不许猜，查官方文档 + 最小实测**）

1. `PreToolUse` / `PostToolUse` 的 `matcher` 语法能否匹配到**具体文件路径**，
   还是只能匹配工具名（`Write` / `Edit`）
2. hook 能否从 stdin 拿到被写入的**文件路径与内容**
3. `PostToolUse` 的 stdout **是否进上下文** —— 上一轮查到的是
   「只有 SessionStart / UserPromptSubmit / UserPromptExpansion 三类 stdout 进上下文，
   其余只写 debug log」。**如果 PostToolUse 不进上下文，整个赌注需要改形态**
   （改用 `UserPromptSubmit` + 条件判断，或接受它只做静默拦截）

✋ 核验完先把结论给我，再决定做不做。**第 3 条若不成立，本节直接砍掉，不要硬凑。**

### 如果成立，附带的更大问题

上一轮判定 §九 A/D/F/G/H/K「不可拆」的理由是**触发是内部状态**
（"我准备说完成了"、"已经循环两次了"），一句 description 抓不住。

**五问自查**：可触发（用新工具时）· 有行为差量（多一步校准）· 不可推导 ·
