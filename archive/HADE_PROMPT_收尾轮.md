## F2 · hash 探针（堵这轮引入的缺口）

**问题**：`~/.claude/CLAUDE.md`（生效的本体）与
`plugins/hade-core/install/CLAUDE.md`（版本化的副本）靠手动同步，无机制保证。
重构前只有一份本体，不存在这个问题 —— 这是三层结构的代价。

**动作**：在 `hade-core/hooks/session-start.js` 里加一段 —— 比对两份文件的 hash，
不一致时把警告吐进上下文（连同两边的行数与 mtime，方便判断哪边是新的）。

**约束：**
- **只报警，不自动同步**。自动同步会在判断错方向时静默覆盖掉正确的那份
- 一致时**不要输出任何多余的话** —— 每 session 都跑，噪音会稀释指针本身
- 读文件失败（路径不存在等）要静默跳过，不能让探针本身弄崩 SessionStart

**校准（不许跳过，这是上一轮吃过亏的地方）：**
1. 两份一致时开新 session → 确认**无输出**
2. 故意改副本一个字 → 开新 session → 确认**报得出来**，且信息足够判断哪边新
3. 改回来 → 确认恢复静默

上一轮出过三次"假 0% 报告"，任一次轻信都会去优化一个根本不存在的问题。
**没经过第 2 步的探针，不算数。**

## F3 · 四处记录清理（顺手，低风险）

1. **数字**：`PLAN-AND-EXECUTION-LOG.md` 汇总表写「−197 / −18.1% / 892 行 / 72167 字节」，
   实测是「**−198 / −18.2% / 891 行 / 72327 字节**」。
   最后两次提交后汇总表没回头更新。改正，并注明字节口径是 **CRLF**。

2. **记账口径补第三格**：现有分类是「规则性新增/调整」与「范围声明扩容」两格。
   §七 完整性自检那处**加例外条款**被归进了第一格 ——
   但给一条安全闸门开口子，风险级别高于加一条新规则。
   补第三格 **`安全条款例外化`**，把那处归进去，并补一句
   「为什么这个例外不会被滥用」（前提条件是什么、谁来确认）。

3. **§七「比上次」的基准**（**唯一一处动 Global，走预警协议**）：
   完整性自检里 `行数比上次骤降（>30%）→ 异常`，结构审查已发现「比上次」未定义
   （比上次编辑？比上份快照？）但只提议未解决。
   **现在有确定基准了**：`git show HEAD:plugins/hade-core/install/CLAUDE.md`。
   把「比上次」定义为「比仓库 HEAD 版本」。

   验证：故意造一次 40% 的行数下降 → 自检应正确报警；
   再造一次"计划内外移"→ 应命中例外条款不误报。

## F4 · hook 三项核验（**只查文档 + 最小实测，不写实现代码**）

**这决定下一轮最大的赌注成不成立**，所以要在收尾轮就把结论拿到。

**背景**：R1（触发欠敏）上一轮**没有被解决，只是被绕开了**。
`local-storage-safety` 两种形态都是 0/9，它是个不会自己醒来的工具。
但已验证的事实是：**SessionStart hook 100% 触发，description 匹配 0%** ——
差别不在内容写得好不好，在**触发权归谁**。

设想是把校验器挂到 `PostToolUse`，由"文件被改了"这个客观事件触发，
而不是由模型"想不想调工具"触发。

**要核验的三条（对官方文档 + 最小实测，不要凭训练记忆）：**

1. `PreToolUse` / `PostToolUse` 的 `matcher` 能否匹配到**具体文件路径**，
   还是只能匹配工具名（`Write` / `Edit`）
2. hook 能否从 stdin 拿到**被写入的文件路径与内容**
3. **`PostToolUse` 的 stdout 是否进上下文** ——
   已知的是「只有 `SessionStart` / `UserPromptSubmit` / `UserPromptExpansion`
   三类 stdout 进上下文，其余只写 debug log」。

**第 3 条是生死线。** 如果 `PostToolUse` 的输出到不了模型眼前，
整个赌注要换形态（改挂 `UserPromptSubmit` + 条件判断，或接受它只做静默拦截并另想办法回传）。
