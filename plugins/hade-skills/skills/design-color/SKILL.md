## 选色前先跑校验（§十.9 设计三问的可执行版）

本 skill 附带确定性校验器，把 §十 里**可判定的数值约束**变成一条命令。
不替代下面的规则，是它的第二层保险：哨兵防「没想起来」，脚本防「想起来了但漏了一项」。

**脚本路径**：本 skill 载入时，最开头的 `Base directory for this skill:` 一行给出了绝对路径。
脚本在它下面的 `scripts/check_colors.py`。**用那一行拼接，不要猜路径** —— 路径含版本号
（…/hade-skills/<版本>/skills/design-color），每次版本更新都会变，猜必然落空。

```bash
BASE="<把上面 Base directory 那一行的路径填进来>"
python "$BASE/scripts/check_colors.py" "#ff3b30" "#34c759"        # 逐色查 §十.1 通道/禁区
python "$BASE/scripts/check_colors.py" --area large "#007aff"     # §十.8 面积约束
python "$BASE/scripts/check_colors.py" --palette "#a" "#b" "#c"   # §十.6 密度 + §十.7 并置
python "$BASE/scripts/check_colors.py" --pair "#8e8e93" "#34c759" # §十.3 翻牌姊妹色
```

退出码 0 = 通过，1 = 有违规。

**铁律：不许手算代替脚本，也不许启动了脚本却不等结果。**
给出**任何**色值前先跑一遍 —— 包括你已经判断出"原色不合格"、正在推荐替代色的时候，
那一步最容易错。

实测证据（2026-08-24）：面对三个 S≈26% 的禁区色，HADE 正确诊断了问题、正确说出
"要把 S 拉到 70+"，却以"手算过了，不用等脚本"跳过校验，然后推荐了
`#2e6da4`(S=56%) `#c0392b`(S=63%) `#27963f`(S=59%) —— **三个替代色全部仍在禁区**。
规则记得、诊断对、目标说得准，手算色值时照样全错。
§十.9 的 OutingTool V2.0 反例（十二色全在 S≈54）是同一种失败。

这类错误与触发率无关，触发得再准也挡不住 —— 只有确定性检查能。

**脚本真的跑不了时**（权限被拦 / 无 python）：明确告诉用户"脚本未执行，以下是手算"，
然后**逐色写出 H/S/L 三个数**再下判断，不得跳过过程直接给结论。
公式：`L=(max+min)/2`，`S=delta/(1-|2L-1|)`（delta=(max-min)/255）。
给替代色时同样要逐个算完再给 —— 上面那次翻车正是替代色没算。

> 跨所有工具共享的色彩规范。
> 2026-04-09 从 OKLCH 全色域手工筛选确立。
> 2026-04-16 重构为"双通道 + 中间地带禁区"模型，定义 H/S/L 三轴精确约束，消除"浑浊低级"中间档。

### 1. 双通道模型

**通道 A · 彩色（Chroma）**
- S：70–100%（70 是底线，仅迫不得已；日常建议 80+）
- L：48–60%
- H：允许粉红、红、红橙、橙红、橙、黄、绿、翠绿、青绿、青、青蓝、蓝、靛、紫、紫红
- H 禁用：**玫红**（≈H335）、**黄绿**（≈H80）— 双色骑墙，审美不符

**通道 B · 无彩色（Grayscale）**
- S：≤ 5%
- L 档位：
  - 深灰 L 15–35% — 文字主色 / 深色块
  - 中灰 L 50–60% — 双态中的"未做""未激活"态
  - 浅灰 L > 75% — 禁用（黑字场景除外）

**禁区 · 中间地带**
- S 6–69% — 严禁
- 原因：饱和度不上不下，色相被灰"污染"→ 浑浊、廉价感
- 用户原话："如果要深色我倾向用深灰色，带杂色的话就会显得很低级"

### 2. 文字色筛选层（按场景收紧）

色板是审美池；具体能用哪些，看文字色：

| 场景 | 规则 |
|------|------|
| 色块 + 白字 | 保留白字对比度 ≥ 4.5:1 的色 → 黄自动出局 |
| 色块 + 黑字 | 保留黑字对比度 ≥ 4.5:1 的色 → 黄、浅色合法 |
| 纯色 / 无文字 | 色板全域自由 |
| 颜色搭配（无色块文字） | 色板全域自由 |

**关键**：黄不是永久禁 — 白字场景筛掉，其他场景可用。

**黑字路线（可选）**：
- "色块 + 黑字 + 浅底（L 85+）" 是合法的另一种路线，不是默认
- 选择此路线的项目必须**全项目统一使用**，不可与"彩色块 + 白字"混用（违反 §十.5 原则 4 "页面内文字色统一"）
- 适用场景：信息密度高 / 文档型 / 纸质感界面

### 3. 翻牌姊妹色（双态切换）

双态切换（未做/已完成、关/开、未选/已选）两色必须为「同色板姊妹」：
- 亮度差 ≤ 10%
- 组合模式（任选其一）：
  - 通道 A + 通道 A：同色板，靠色相差 或 饱和度差 区分
  - 通道 A + 通道 B：灰（未做）+ 彩（完成），最通用
- 禁：跨越禁区（如 S=30% 的半饱和色）
- 注：瞬切，不加渐变动画（渐变会路过中间地带，违背色板哲学）

### 4. 参考锚点（iOS / Apple 系统色）

位于通道 A 中心的坐标，不是穷举：
```
红 #ff3b30   橙 #ff9500   绿 #34c759
蓝 #007aff   青 #30b0c7   粉 #ff2d55
靛 #5856d6   紫 #af52de   灰 #8e8e93（通道 B）
```
色板允许在约束内自由取值，锚点只标定"舒服区"坐标。

### 5. 关键原则

1. **色板 ≠ 文字安全区** — 色板是审美选择，白字/黑字筛选是场景层
2. **黑字也好看** — 但色块+文字默认白字更协调
3. **禁中间地带** — 纯色要纯，灰色要灰，不混
4. **页面内文字色统一** — 同一页面不混用黑白
5. **锚点非唯一** — iOS 色是坐标不是清单，允许在约束内取任意值

### 6. 页面级色彩密度 (→ 元C)

**触发**：设计一个页面 / 多列表格 / 多标签组件 / 任何"会出现一组并列彩色元素"的场景。
**动作**：
- 同屏不同色相 **≤ 6 种**（同色相重复使用不计数，如整页用同一蓝作主色可无限复用）
- 语义项超过 6 个 → 最弱语义的几项退化为通道 B（灰），彩色留给 ≤ 6 种核心语义
- 整页彩 vs 中性比例参考：**彩 ≈ 30%，中性 ≈ 70%**
**原因**：色彩是点睛不是铺底；满屏彩色 → 语义信息反而糊成一片。
**反例**：OutingTool 早期 7 列 chip 全彩并列 → 视觉噪音，用户读表时色相先声夺人压过数据本身。

### 7. 多色并置协调 (→ 元C)

**触发**：把多个彩色元素放在**相邻位置**（相邻 chip / 相邻列表头 / 相邻按钮 / 同行并列标签）。
**动作**：
- 相邻彩色的色相间距 **≥ 30°**（12 色相环分法）
- 禁止相邻同色相族并置（如 红+红橙 15° / 青+青蓝 15°）
- 多项并置优先"色相环均匀分布"（360°/N），或走"三色分割 (120°) / 互补 (180°)" 和谐模板
**原因**：色相太近 → 打架，眼睛分不清边界，两个色都被削弱。
**反例**：两列表头分别用 #ff3b30（红）和 #ff2d55（粉），色相差仅 15° → 并列时像"同一种红但显色不一致"。

### 8. 面积约束（大 / 小） (→ 元C)

**触发**：选色前先判断要用在多大面积上。
**动作**：
- **小面积**（chip / badge / 图标 / 按钮 / 单元格 chip / 标签）：§十.1 通道 A 约束即可（S 70-100, L 48-60）
- **大面积**（整行背景 / 整列背景 / 弹窗底 / 页面底 / 大色块）：**禁用通道 A**，只准用：
  - 通道 A + L ≥ 85%（浅色柔和底）
  - 通道 B（灰，任档位）
  - 白 / 深灰 L 15-25（深色沉底）
**原因**：中饱和中明度色作"点缀"合法；铺成大面积 → 糊眼睛 / 视觉疲劳 / 压抑。
**反例**：把 #007aff（L≈50）做成整列背景 —— 单色合法，但整列铺开后无法长时间阅读。

### 9. 设计三问（强制审查） (→ 元C)

**触发**：任何新选色 / 新做色板 / 新组件色方案前（不论"我觉得好看"还是"看起来像苹果风"）。
**动作**：强制自答三问，答不上或踩线 → 停手重选：
1. **HSL 读出** — S 是否在 6-69 禁区？L 是否在通道 A (48-60) 或通道 B (15-35 / 50-60 / <5) 合法档？
2. **面积判定** — 小 / 大？大面积必须走 §十.8
3. **并置判定** — 周围有其他彩色吗？色相间距 ≥ 30°？同屏色相 ≤ 6 吗？
**原因**：§十.1 ~ §十.8 条款再多也救不了"拍脑袋选色" → 强制三问 = 防止"我觉得好看"直接下手。
**反例**：OutingTool V2.0 COL_COLORS 选了 12 色全在 S≈54、L≈36 —— 如果走过三问第 1 条就会被挡下（S 在禁区）。结果上线后"浑浊低级 / 太暗压抑 / 色相不协调"三症状齐发，正是 §十 预言的违规后果。
